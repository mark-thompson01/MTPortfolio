Managed Switch Configuration

Initial setup and lab VLAN/trunk configuration for the Cisco Catalyst switching layer, walked through step by step with terminal output.

Switch001

Cisco Catalyst 2950G-48-EI (WS-C2950G-48-EI)

IOS Version
12.1(22)EA4a, RELEASE SOFTWARE (fc1)
Management IP
192.168.50.2 /24 (VLAN 1)
Cluster
MTLabs
Role
Access layer switch — trunked uplink to Switch002 (3550)

Initial Configuration Dialog

13 steps

First boot of Switch001. Working through Cisco's System Configuration Dialog to set the hostname, enable secret, line passwords, management VLAN IP, and cluster settings before saving to NVRAM.

1

Cold start & setup dialog prompt

Switch boots cold, displaying the WS-C2950G-48-EI hardware details, then prompts to enter the initial configuration dialog. Answered yes to begin.

2

Basic management setup & hostname

Enabled basic management setup and assigned the hostname Switch001, then moved into the enable secret prompt.

3

Enable secret, enable password & VTY password

Set the enable secret, legacy enable password, and virtual terminal (VTY) password, declined SNMP management, and the interface summary begins.

4

Interface summary (Fa0/1–0/19)

Dialog lists the current interface summary — every FastEthernet port unassigned and down, VLAN1 flagged as needing a valid configuration.

5

Interface summary (Fa0/26–0/48, Gi0/1–0/2)

Summary continues through the remaining Fast Ethernet ports and both Gigabit uplinks, then prompts for which interface to use for management connectivity.

6

Selecting VLAN1 as the management interface

Declined defaulting to all interfaces, then explicitly named vlan1 as the management interface.

7

Configuring the VLAN1 IP address

Assigned 192.168.50.2 with a 255.255.255.0 (/24) mask to VLAN1, and opted in to enabling the switch as a cluster command switch.

8

Confirming the /24 mask & cluster prompt

Dialog confirms the Class C network (192.168.50.0, /24) and re-confirms enabling the switch as a cluster command switch.

9

Naming the cluster: MTLabs

Named the cluster MTLabs to group the lab's managed switches under one command switch.

10

Generated configuration script (part 1)

Cisco generates the resulting configuration script from the dialog answers — hostname, enable secret, VTY lines, and the VLAN1 IP address.

11

Generated configuration script (part 2)

Script continues, stubbing out each FastEthernet interface for later per-port configuration.

12

Saving the configuration to NVRAM

Selected option [2] Save this configuration to nvram and exit to commit the initial setup.

13

Configuration saved & ready for login

Configuration builds successfully ([OK]), VLAN1's line protocol comes up, and the switch is ready to log in for lab configuration.

Lab VLAN, Interface & Trunk Configuration

17 steps

With the base setup complete, built out the lab's VLAN structure, assigned access ports to each device, configured the 802.1Q trunk to Switch002, and verified the result.

1

Back at the CLI

Returning to the CLI with a clean Switch001> prompt, ready to begin the lab-specific configuration.

2

Entering privileged EXEC mode

Authenticated into privileged EXEC mode with enable.

3

Entering global configuration mode

Dropped into global configuration mode with conf t to begin building out VLANs and interfaces.

4

Setting the MOTD banner

Set a message-of-the-day banner: MTPortfolio Lab Network.

5

Creating the lab VLANs

Created and named the lab's VLANs: 10 – Servers, 20 – Infrastructure, 40 – Clients, and 99 – Native.

6

Management interface IP & default gateway

Configured interface vlan 1 with description Management, IP 192.168.50.2/24, and set the default gateway to 192.168.50.3.

7

Fa0/1 — Management access port

Configured Fa0/1 as an access port on VLAN 1 for management, enabling PortFast (correcting a typo on the switchport access vlan command along the way).

8

Fa0/2 — Hyper-V host

Configured Fa0/2 as an access port on VLAN 20 (Infrastructure) for the Hyper-V host, with PortFast enabled.

9

Fa0/3 — TrueNAS server

Configured Fa0/3 as an access port on VLAN 10 (Servers) for the TrueNAS server.

10

Fa0/4 — Raspberry Pi 5 DNS server

Configured Fa0/4 as an access port on VLAN 10 for the Raspberry Pi 5 DNS server, with PortFast enabled.

11

Fa0/5 — Raspberry Pi 3 NAS

Configured Fa0/5 as an access port on VLAN 10 for the Raspberry Pi 3 NAS (again correcting a typo on the access VLAN command).

12

Fa0/23 — 802.1Q trunk to Switch002

Configured Fa0/23 as a trunk to Switch002 (3550): trunk mode, native VLAN 99, and allowed VLANs 1, 10, 20, 40, 99.

13

Console & VTY passwords, saving to NVRAM

Set console and VTY line passwords with synchronous logging, then saved the running configuration with write memory.

14

Verifying VLANs (before trunk cleanup)

show vlan brief confirms VLANs 10 (Servers), 20 (Infrastructure), 40 (Clients), and 99 (Native) with their assigned ports.

15

Verifying VLANs (after trunk configuration)

Re-running show vlan brief after the trunk was configured — Fa0/23 has moved off the default VLAN 1 port list as expected.

16

Verifying the trunk

show interfaces trunk confirms Fa0/23 is trunking with 802.1Q encapsulation, native VLAN 99, and VLANs 1, 10, 20, 40, 99 allowed and active.

17

Verifying spanning tree

show spanning-tree summary confirms the switch is running PVST with all five VLAN instances in a forwarding state — no blocking, no loops.

Initial Configuration Dialog

10 steps

First boot of Switch002. Same System Configuration Dialog walkthrough as Switch001 — hostname, enable secret, line passwords, management VLAN IP, and cluster settings — before saving to NVRAM.

1

Cold start & setup dialog prompt

Switch reboots cold into the System Configuration Dialog. Answered yes to enter the dialog and yes to basic management setup, then set the hostname to Switch002.

2

Enable secret prompt

Dialog continues from the hostname entry into the enable secret prompt.

3

Enable secret, enable password & VTY password

Set the enable secret, enable password, and VTY password, declined SNMP management, and the interface summary begins (VLAN1, Fa0/1–0/8).

4

Interface summary (Fa0/3–0/19)

5

Interface summary & management interface prompt

6

Configuring the VLAN1 IP address

7

Naming the cluster & generated script (part 1)

Joined the existing MTLabs cluster. Cisco generates the resulting configuration script — hostname, enable secret, enable password, VTY password, and the VLAN1 IP address.

8

Generated configuration script (part 2)

9

10

Configuration saved & ready for login

Configuration builds successfully ([OK]), and the switch is ready to log in for lab configuration.

Lab VLAN, Routing & Trunk Configuration

17 steps

Switch002 operates at Layer 3, so beyond VLANs and trunking this build also covers inter-VLAN routing via SVIs, a static default route, a routed uplink to the SOHO router, and root bridge priority tuning.

1

Back at the CLI

Returning to the CLI with a clean Switch002> prompt, ready to begin the lab-specific configuration.

2

Entering configuration mode

Authenticated into privileged EXEC mode with enable, then dropped into global configuration mode with conf t.

3

Setting the MOTD banner

Set a message-of-the-day banner: MTPortfolio Lab Network.

4

Enabling IP routing

Enabled ip routing — the Catalyst 3550 is a Layer 3 switch, so it handles inter-VLAN routing for the lab rather than relying on an external router-on-a-stick.

5

Creating the lab VLANs

Created and named the same lab VLANs as Switch001: 10 – Servers, 20 – Infrastructure, 40 – Clients, and 99 – Native.

6

Configuring SVIs for inter-VLAN routing

Gave each VLAN a routable gateway via SVIs: VLAN1 (Management, 192.168.50.3), VLAN10 (Servers, 192.168.10.1), VLAN20 (Infrastructure, 192.168.20.1), and VLAN40 (Clients, 192.168.40.1).

7

Adding a static default route

Added a static default route (0.0.0.0/0 via 192.168.50.1) so lab traffic has a path out toward the SOHO router.

8

Fa0/1 — Management access port

Configured Fa0/1 as an access port on VLAN 1 for management, with PortFast enabled.

9

Fa0/2 — Win11 client

Configured Fa0/2 as an access port on VLAN 40 (Clients) for a Windows 11 client machine, with PortFast enabled.

10

Fa0/23 — 802.1Q trunk to Switch001

Configured Fa0/23 as the trunk back to Switch001 (2950): 802.1Q encapsulation, trunk mode, native VLAN 99, and allowed VLANs 1, 10, 20, 40, 99.

11

Fa0/24 — Routed uplink to the SOHO router

Converted Fa0/24 to a routed port (no switchport) and assigned 192.168.1.2/24 as the uplink to the SOHO router.

12

Setting spanning-tree priority (root bridge)

Set spanning-tree priority to 4096 on VLANs 1, 10, 20, 40, and 99, making Switch002 the root bridge for the lab topology.

13

Console & VTY passwords, saving to NVRAM

Set console and VTY line passwords with synchronous logging, then saved the running configuration with write memory.

14

Verifying VLANs

show vlan brief confirms VLANs 10 (Servers), 20 (Infrastructure), 40 (Clients), and 99 (Native) with their assigned ports.

15

Verifying the trunk

show interfaces trunk confirms Fa0/23 is trunking with 802.1Q encapsulation, native VLAN 99, and VLANs 1, 10, 20, 40, 99 allowed and active.

16

Verifying the routing table

show ip route confirms the directly connected VLAN 1, 10, 20, and 40 subnets, plus the static default route out via 192.168.50.1.

17

Verifying spanning tree

show spanning-tree summary confirms Switch002 is now the root bridge for all five VLAN instances, with everything in a forwarding state.

Initial Boot & Setup Wizard

10 steps

Dell's PowerConnect boot process differs from Cisco's — a Boot Menu handles factory resets and code loading, while an on-box Setup Wizard walks through the initial privilege account and management IP.

1

Restoring factory defaults from the Boot Menu

The full Boot Menu option list appears. Selected 10 – Restore configuration to factory defaults, confirmed y, then selected 1 to start the operational code.

2

Setup Wizard begins

On boot, the Setup Wizard offers to run — answered Y. Declined SNMP management setup in Step 1, then began Step 2 by entering the privilege-15 username MT.

3

Volume info & default boot prompt

Tail end of a file-system/volume configuration display, followed by the default Boot Menu prompt — selected 1 to start the operational code.

4

Password & management IP prompt

Step 2 continues with the password entry, then Step 3 begins — prompted for the switch's management IP address on the default VLAN, with a DHCP option offered.

5

Back at the Boot Menu

The Boot Menu's full option list appears again. Selected 10 to restore factory defaults, confirmed y, then 1 to reboot into the operational code.

6

Setup Wizard runs again

Setup Wizard runs again — Y to proceed, SNMP declined, and Step 2 begins with the username MT.

7

Volume & file-system configuration

Full volume/file-system configuration details are displayed — volume label, sector counts, FAT entry size, directory structure — followed by the Boot Menu banner.

8

Entering the Boot Menu manually

Volume information continues (bytes per sector, FAT table copies, free space), then at the default prompt selected 2 to enter the Boot Menu manually rather than let the operational code auto-start.

9

Selecting factory reset again

Inside the Boot Menu, the full 13-option list is shown; began entering 10 to restore factory defaults.

10

Confirming the factory reset

Confirmed selection 10, with y ready at the Are you SURE you want to delete the configuration? prompt.
