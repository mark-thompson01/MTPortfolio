Microsoft Entra ID P2 Trial and Licensing

8 steps

Connect Health requires an Entra ID P1 or P2 license at the tenant level, a tier this lab does not carry by default. Activated the free 30 day P2 trial under SyncAdmin, an account already provisioned as a Global Administrator for hybrid identity work, then assigned the license before touching the agent installer.

1

SyncAdmin account overview

SyncAdmin, the account used for hybrid identity administration in this tenant, with UPN syncadmin@markandrewt01outlook075.onmicrosoft.com.

2

Confirming the Global Administrator role

SyncAdmin already carries Global Administrator, the role needed to activate a tenant wide trial and manage licensing. Hybrid Identity Administrator is visible in the same list as the narrower alternative for agent registration alone.

3

Opening Licenses

Opened Licenses under Microsoft Entra ID in the Azure portal to start the trial activation.

4

Activating the Entra ID P2 free trial

Expanded the Microsoft Entra ID P2 free trial panel, confirmed the default 100 license count and 30 day window, and clicked Activate.

5

Completing trial signup

Signed in as SyncAdmin on the trial signup page and clicked Continue to complete activation for the tenant.

6

Entra ID P2 now listed

Back on the Microsoft Entra ID overview, the license list now shows Entra ID P2 alongside the tenant's existing 10 synced users.

7

Confirming license availability

Licenses > All products confirms Microsoft Entra ID P2 is active with 100 total licenses and 100 available, none assigned yet. This blade shows totals only; assignment happens elsewhere.

8

Assigning the license from the M365 admin center

Assigned the P2 trial license to SyncAdmin from the Microsoft 365 admin center, the surface that actually handles license assignment. The panel also flags the trial's expiration date of 10/12/2026.

Lesson Learned License assignment is not available from the Licenses blade in the Azure portal, it only reports totals and availability. Assigning a license to a specific account has to happen from the Microsoft 365 admin center's user details panel instead, a small but easy to miss distinction between the two admin surfaces.
Constraint The P2 trial expires on 10/12/2026, 30 days from activation. A calendar reminder is set for day 25 to either cancel the trial or unassign the license, since ongoing P2 licensing is not something this lab environment needs to carry once the agent has been demonstrated and documented.

Downloading and Installing the Connect Health Agent

7 steps

With P2 active, moved to SRV-ADMIN01 to download and install the Connect Health agent for Sync. Unlike the core Entra Connect installer, this agent is not bundled into the Entra admin center flow, it lives on its own Microsoft Download Center page.

1

Microsoft Download Center

Located the agent on microsoft.com, version 4.5.2549.0, published 2/23/2026, and clicked Download.

2

Installer in Downloads

MicrosoftEntraConnectHealthAgentSetup.exe landed in Downloads on SRV-ADMIN01, sitting next to the original AzureADConnect installer from the earlier Entra Connect sync lab.

3

Selecting the service to monitor

Checked Microsoft Entra Connect Sync Service as the role to monitor, leaving AD Domain Service, AD Federation Service, and Microsoft Identity Manager Service unchecked, since SRV-ADMIN01 is the sync server in this lab, not a domain controller or federation server.

4

Accepting license terms

Accepted the license terms and conditions and clicked Install.

5

Registering with SyncAdmin

Mid install, the wizard prompted for a sign in to register the agent against the tenant. Selected the SyncAdmin account already active on the box, matching the Global Administrator credential used for the trial and the original Entra Connect install.

6

Setup in progress

Setup proceeded with the registration handshake to the Microsoft Entra Connect Health service running in the background.

7

Setup successful

Setup Successful, with links to the Setup Bundle, Installation, and Registration logs. The agent registered on the first attempt, no manual re-registration or connectivity workaround needed.

Verifying Registration and Exploring the Dashboard

3 steps

The point of this lab was demonstrating the operational side, not just getting an install to finish. Everything below runs entirely in the cloud, in the Entra admin center, exactly the kind of no RDP needed visibility Connect Health exists to provide once it is wired up.

1

Locating Connect Health from Entra Connect

From Microsoft Entra Connect > Connect Sync, the Health and Analytics section links out to Microsoft Entra Connect Health, confirming the two are related but separate blades in the admin center.

2

Sync services, healthy

Sync services lists the tenant's sync service with a status of Healthy, zero active alerts, and a last updated timestamp inside the expected 30 minute reporting cycle. This is the registration proof, SRV-ADMIN01's agent is reporting in.

3

Sync errors, clean across every category

Sync errors shows zero across every category: Duplicate Attribute, Data Mismatch, Data Validation Failure, Large Attribute, Others, Federated Domain Change, and Role Membership Match Failure. A clean report here is what an admin would check first thing every morning, without touching the sync server at all.

Note Connect Health has no local console of its own. Everything above lives entirely in the cloud, with the agent on SRV-ADMIN01 only responsible for collecting data and phoning it home on a roughly 30 minute cycle. If the agent ever lost connectivity to the health service, the fallback would be the same tools that predate Connect Health entirely: Synchronization Service Manager (miisclient.exe) and Event Viewer's Directory Synchronization log, both run directly on the sync server.
